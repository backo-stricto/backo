
# Routing

This part present the API RESTFULL generated by backo.

When you call

```python
mybackoffice.build_routes(flask)
```
Api routes are generated

## Prefix

You can change prefix and version for route. 

```python
mybackoffice=Backoffice( "myApp", "1.2.3" )
mybackoffice.build_routes(flask, "my_company")
# Start the flask server
flask.run(host="0.0.0.0", port=80)
```

will build routes under :

```text
http://localhost/my_company/myApp/1.2.3/...
```


## CRUD

CRUD (**C**reate, **R**ead, **U**pdate, **D**elete ) operations via API


### Get by _id

use `GET` http method.
Return the object of this collection *by _id*.

The path is : 

```text
/{ my-app-name }/{ collection name }/{ _id }
```
example :

```bash
curl -X GET 'http://localhost/myApp/users/123'
```
Answers can be :

| code | data             | Description                              |
| ---- | ---------------- | ---------------------------------------- |
| 200  | JSON object data | the requested item                       |
| 401  | None             | you are not authorized to view this item |
| 404  | None             | item not found                           |
| 500  | None             | server-side error                        |

(selection_route)=
### Selection

use `GET` or `POST` http method.

The `GET` path can be : 

* For a full query 
```text
/{ my-app-name }/{ collection name }/?{ query string }
```
* For a full query with sorting 
```text
/{ my-app-name }/{ collection name }/?{ query string }{ _sort = < str > }
```

* A query with pagination
```text
/{ my-app-name }/{ collection name }/?{ query string }&{ _page = <int> }
/{ my-app-name }/{ collection name }/?{ query string }&{ _page = <int> }&{ _skip = <int> }
/{ my-app-name }/{ collection name }/?{ query string }&{ _total = 1 }
```

* Getting the total for a query 
```text
/{ my-app-name }/{ collection name }/?{ query string }&{ _total = 1 }
```

#### The query string

Get a list of objects matching the query string. The query string can be with this format

| key                    | value     | description                                                                                                                                                                  |
| ---------------------- | --------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| \<field\>              | \<value\> | matches items where `<field>` equals `<value>`. Example: `surname=donald` finds all items where surname equals to "donald".                                                  |
| \<field\>.\<operator\> | \<value\> | matches items where `<field>` satisfies `<operator>` with `<value>`. Example: `age.$lt=12` finds items where age is less than 12.                                            |
| \<field\>.\<subfield\> | \<value\> | Matches items where `<field>` is a nested dictionary containing `<subfield>` equal to `<value>`. Example: `address.number=1` matches items where address.number equals to 1. |

List of available operators :

| operator | syntax | example | description |
| - | - | - | - |
| $and | ( "$and", [ condition, condition ] ) | ( "\$and", [ ( "\$gt", 1 ), ( "\$lt" : 2 )]) | Do an *and* on conditions |
| $or | ( "$or", [ condition, condition ] ) |  ( "\$or", [ ( "\$gt", 10 ), ( "$eq" : 0 )]) | Do an *or* on conditions |
| $eq | ( "$eq", value ) |  ( "\$eq", "toto" ) | Equality |
| $ne | ( "$ne", value ) |  ( "\$ne", "toto" ) | Not equal |
| $lt | ( "$lt", value ) |  ( "\$lt", 1 ) | Less than |
| $lte | ( "$lte", value ) |  ( "\$lte", 1 ) | Less than or equal |
| $gt | ( "$gt", value ) |  ( "\$gt", 1 ) | Greater than |
| $gte | ( "$gte", value ) |  ( "\$gte", 1 ) | Greater than or equal |
| $not | ( "$not", condition ) |  ( "\$not", ... ) | Not |
| $reg | ( "$reg", regexp ) |  ( "\$reg", r'Jo' ) | A regular expression; match only on strings (match "start with Jo" in this example.) |
| $contains | ( "$contains", condition ) |  ( "\$contains", ( "$reg", r'^Jo' ) ) | a list contains one or more elements matching the condition |



In any cases the request returns a HTTP status `200` with that JSON object:

```python
{
    "result": # list of dict containing objects matched
    "_skip": # the _skip given in the request
    "_page": # the _page given in the request
}
```

#### Example
Select all users whose name includes 'do' and present the result list with 10 items per page, sorted by surname.
```bash
curl -X GET 'http://localhost/myApp/users/?name.$re=do&_page=10&_sort=$.surname'
{
    "result" : [ ... ]
    "_skip" : 0
    "_page" : 10
}
```

Getting the total
```bash
curl -X GET 'http://localhost/myApp/users/?name.$re=do&_total=1' 
{ "total" : 32 }

```

An example with a post for more complex filter

```bash
curl -X POST 'http://localhost/myApp/users -d { "$or" : [ ( "$.surname", "Doe" ), ( "$.incomes.salary" : ( "$gt", 60000 ) ) ] }'  
{
    "result" : [ ... ]
    "_skip" : 0
    "_page" : 10
}
```

### Create

Create a new item for the collection `collection name`.


use `POST` http method.

The path is : 

```text
/{ my-app-name }/{ collection name }
```
example :

```bash
curl -X POST 'http://localhost/myApp/users/' -d '{"name":"John","surname":"Rambo"}'
```
Answers can be :

| code | data             | Description                              |
| ---- | ---------------- | ---------------------------------------- |
| 200  | JSON object data of the created object  | The object is created                       |
| 401  | None             | you are not authorized to create item |
| 404  | None             | collection not found                           |
| 500  | None             | server-side error                        |


### Update


use `PUT` http method.

The path is : 

```text
/{ my-app-name }/{ collection name }/{ _id }
```

Example :

```bash
curl -X PUT 'http://localhost/myApp/users/1234' -d '{"name":"Johnny"}'

```
Will modify the users with _id *1234* and return the modified object.


```{tip}

You don't need tu send the full object to motify just a part of it. 

```


Answers can be :

| code | data             | Description                              |
| ---- | ---------------- | ---------------------------------------- |
| 200  | JSON object data of the modified object  | The modified                       |
| 401  | None             | you are not authorized to modify this item |
| 404  | None             | collection or item not found                           |
| 500  | None             | server-side error                        |



### Delete

Delete an existing object by `_id`.


use `DELETE` http method.

The path is : 

```text
/{ my-app-name }/{ collection name }/{ _id }
```

Example :

```bash
curl -X DELETE 'http://localhost/myApp/users/1234'

```
Delete the user that has _id = *1234*.


Answers can be :

| code | data             | Description                              |
| ---- | ---------------- | ---------------------------------------- |
| 200  | None  | The object is successfully deleted                       |
| 401  | None             | you are not authorized to delete this item |
| 404  | None             | collection or item not found                           |
| 500  | None             | server-side error                        |

## Validation

You can check the compliance of an object to to the Item with this specific routes. The backoffice server will return an error message if the structure is not comliant

The path is : 

```text
/{ my-app-name }/{ collection name }/_check
```

You must provide a json structure in the body :

| field | type | descrimtion |
| -- | -- | -- |
| item | dict | the data to check. It can be partial, see examples below |
| path | string | the field to check in the item. This is a selector. Please refer to [stricto selectors](https://stricto.readthedocs.io/en/latest/readme.html#selectors) for more details |

The answer is a status 200 message with a json structure :

| field | type           | descrimtion                                           |
| ----- | -------------- | ----------------------------------------------------- |
| error | string or null | if null ther is no error, otherwise the error message |


Examples :

```bash
curl -X POST 'http://localhost/myApp/users/_check' -d '{ "item" : { "name" : "John", "surname" : 32 }, "path" : "$.surname" }'
# will check surname an return a response.data like 
{
    'error' : "Must be a string"
}
```

The response is a *status 200* even if the check returns an error. The request is correct.

```bash
curl -X POST 'http://localhost/myApp/users/_check' -d '{ "item" : { "surname" : "Johnny" }, "path" : "$.surname" }' 
# will check surname an return a response.data like 
{
    'error' : null
}


curl -X GET 'http://localhost/myApp/users/_check' -d '{ "item" : { "name" : 23, "surname" : "Johnny" }, "path" : "$.surname" }'
# (only the surname is tested. don't car if name is correct or not)
{
    'error' : null
}
```

## OpenAPI

This route is used to generate the OpenAPI specification of the backoffice.

For a local usage, you can take at look at [documento](https://github.com/backo-stricto/documento) to quickly serve the documentation using either Swagger, ReDoc, Rapidoc...



use `GET` http method.

The path is : 

```text
/{ my-app-name }/_openapi
```

Return the OpenAPI specification in JSON format.

```bash
curl -x GET http://localhost/myApp/_openapi
{
    "openapi": 3.1.0
    "info":
      "title": myApp
      "description": app backoffice powered by Backo
      "version": ""
    "paths":
      "/users":
        "get":
          "summary": List users
          "description": List all existing item in users collection, with eventual filtering.
    ...

```


(action_route)=
## Action

See {doc}`Action` for datails on what is an action.

Each action provides a route :

use `POST` http method.

The path is : 

```text
/{ my-app-name }/{ collection_name }/_actions/{ action name }/{ _id }
```

is used to call an action.


Related to the exemple in {doc}`Action` , this is the way to call the action.

```bash
curl -X POST 'http://localhost/myApp/books/_actions/borrow/666'  -d \
  '{ "user_id" : "1234" "return_date" : "2026-03-17T17:17:33.671533" }'
```



Answers can be :

| code | data             | Description                              |
| ---- | ---------------- | ---------------------------------------- |
| 200  | None  | Action successfully executed                       |
| 401  | None             | you are not authorized to execute this action |
| 404  | None             | collection or item or action not found                           |
| 500  | None             | server-side error                        |

(named_selection_route)=
## Named Selection

See {doc}`Selection` for details on what is a named selection.

Named Selection provides routes like those in {ref}`selections <selection_route>`, but with a new prefix :

```text
/{ my-app-name }/{ collection_name }/_selections_/{ selection name }
```

Please refer to {ref}`selections <selection_route>` for query string, operators, pages, ...
